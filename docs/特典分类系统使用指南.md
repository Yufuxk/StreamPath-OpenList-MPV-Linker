# 特典分类系统使用指南

StreamPath 可以根据视频文件名和所在目录，识别 NCOP、NCED、PV、SP、菜单影像、访谈等特典，并在作品详情中显示分类角标和筛选菜单。你可以修改分类名称与识别别名，也可以为单个资源手工指定类型。

分类使用已有的名称信息，不会自动改名、移动或删除媒体文件。它与作品关联、季集编号、视频版本分别管理。

## 一、快速开始

1. 按平时的方式扫描影视库。已有资源会在后台逐批补齐分类，无需重建媒体库。
2. 打开电视剧详情并选择“特别篇”，在区域右侧的“特典分类”菜单中筛选；电影详情会按资源情况显示“正片与版本”“特典映像”“待确认资源”。
3. 分类不合适时，打开资源卡片的更多菜单或右键菜单，选择“修改特典类型”。
4. 需要统一修改名称、补充旧命名或新增类型时，进入 **设置 → 影视库 → 影视库偏好 → 特典分类管理**。

本功能不会自动为无法确定归属的特典猜测作品。资源尚未关联到作品时，应先使用影视库原有的关联功能。

## 二、详情页怎么看

### 电视剧与动画

- 原有季选择、特别篇、版本选择和卡片继续使用。
- 选择特别篇后，可以按实际存在的类型筛选，菜单同时显示数量；“全部特典”恢复该区域的完整列表。
- 分类角标用于说明内容类型，不代表正式季集编号。NCOP 可以保留已有 S00 集号，手工修改分类也不会修改这个集号。
- 缺少独立单集资料和简介的通用卡片，会在标题下显示真实文件名，便于分辨内容。正式单集资料、简介和封面防剧透仍按原功能使用。
- 筛选只改变当前显示内容，不会改写播放队列、集数顺序或视频版本。

如果 S00 中存在人工标记的“非特典”或尚无明确分类的资源，筛选菜单也会显示对应选项；它们不会被强行归入“其他特典”。

### 电影

| 区域 | 用途 |
| --- | --- |
| 正片与版本 | 已有可信正片身份的资源及其版本 |
| 特典映像 | 已识别或人工指定的特典 |
| 待确认资源 | 已有关联，但还不能确定是正片还是特典的资源 |

没有内容的区域不显示。默认播放优先使用可信正片；只有特典或待确认资源时，需要你显式选择资源，不会自动用 PV 或菜单影像代替正片。

电影特典与待确认资源分别保存观看状态和续播，不进入电影正片的观看汇总或正片继续播放入口。最近播放仍可保留它们各自的资源记录。

## 三、系统如何判断类型

判断顺序是：**人工选择 → 文件名中的明确类型 → 最近的有效父目录中的明确类型 → 通用特典证据 → 尚未分类**。

| 名称或路径示例 | 默认结果 |
| --- | --- |
| `作品.NCOP.01.mkv` | NCOP |
| `NCED/01.mkv` | 从目录识别为 NCED |
| `NCOP&ED/作品.NCED.01.mkv` | NCED，明确文件名优先 |
| `NCOP&ED/01.mkv` | 混合特典，目录同时包含两种具体类型 |
| `作品.PV.CM.01.mkv` | 混合特典 |
| `Specials/01.mkv` | 其他特典 |
| `作品.S00E05.mkv` | 保留 S00 身份；没有具体类型时为其他特典 |
| 普通文件既无类型标记，也无特典目录证据 | 尚未分类 |

`Specials`、`Extras`、`Bonus`、`特典`等名称表示“这里有特典”，**不等于 SP 类型**。具体是片头、预告还是访谈，需要文件名、具体子目录或人工选择进一步说明。

识别兼容大小写、常见全半角字符、编号、复数和点号／空格／下划线／连字符等分隔形式。SP 等短词按词元匹配，`SPY×FAMILY`、`SPIDER-MAN` 不会仅因包含字母 SP 被判为特典。为减少歧义，仍建议把类型标记单独写出。

目录判断限制在当前作品和媒体库的有效边界内，不会把公共上层目录中的关键词应用到整个库。

## 四、默认分类与常用标记

下表列出常用写法，并非所有内置别名。完整别名可在“特典分类管理”中查看。

| 分类 | 常用标记或别名 | 内容建议 |
| --- | --- | --- |
| NCOP | `NCOP`、`Creditless OP`、`ノンクレジットOP` | 无字幕片头 |
| NCED | `NCED`、`Creditless ED`、`ノンクレジットED` | 无字幕片尾 |
| SP | `SP`、`SPs`、`特别篇`、`特別編` | 特别篇、番外 |
| PV | `PV`、`PVs`、`Promo` | 宣传影像 |
| CM | `CM`、`CMs`、`Commercial` | 广告、短宣传 |
| MENU | `MENU`、`MENUs`、`菜单影像` | 已导出的菜单视频 |
| INFO | `INFO`、`INFOs`、`介绍影像` | 介绍、信息类视频 |
| OVA / OAD | `OVA`、`OAV`、`OAD` | 三种写法默认合并为同一类 |
| ONA | `ONA`、`ONAs` | 网络原创动画等附加内容 |
| 预告片 | `Trailer`、`Teaser`、`予告編` | 电影或作品预告 |
| 下集预告 | `NEXT`、`次回予告` | 单独收录的下集预告 |
| 过场动画 | `EYECATCH`、`EVECATCH`、`アイキャッチ` | 过场短动画；兼容已有库的 EVECATCH 写法 |
| 幕后花絮 | `Making Of`、`Behind the Scenes`、`メイキング` | 幕后制作内容 |
| 访谈 | `Interview`、`访谈`、`インタビュー` | 主创或声优访谈 |
| 删减片段 | `Deleted Scene`、`Deleted Scenes` | 未收录片段 |
| 制作特辑 | `Featurette`、`制作特辑` | 制作专题短节目 |
| 短片 | `Short`、`Shorts`、`短片` | 附加短片 |
| 音乐影像 | `MV`、`Music Video`、`音乐影像` | 音乐视频 |
| 活动影像 | `Live Event`、`Stage Greeting`、`舞台挨拶` | 活动、见面会等视频 |
| 混合特典 | 同时含多种具体标记，例如 `PV.CM` | 一个文件确实包含多类内容 |
| 其他特典 | `Specials`、`Extras`、`Bonus`、`映像特典` | 已知是特典，但没有具体类型 |

这些分类描述资源内容，不会替代 TMDB 的作品或季集身份。例如，带 OVA 标记的作品仍需要正确的作品关联。

## 五、修改分类名称与识别别名

打开 **设置 → 影视库 → 影视库偏好 → 特典分类管理**，点击某一分类进行编辑。

| 设置项 | 作用 | 例子 |
| --- | --- | --- |
| 分类名称 | 改变界面上的显示名称 | 将 `NCOP` 显示为“无字幕片头” |
| 识别别名 | 决定哪些名称能触发该分类 | 给 NCOP 增加你的库常用的 `Clean Opening` |

修改显示名不会自动把这个名称变成识别别名，也不会更改已有资源的季集或版本。想同时识别新写法，需要把它加入“识别别名”。

操作步骤：

1. 点击已有分类，修改名称或别名。别名每行一个，也可使用中文或英文逗号分隔。
2. 点击编辑弹窗的“保存”，返回分类管理列表。
3. 点击分类管理主弹窗的“保存”，配置才会正式生效。此时点击“取消”会丢弃本次所有草稿，包括刚添加的类别。

保存后，显示名称立即更新，已有资源的自动分类在后台分批重算；人工指定的分类和人工“非特典”保持。重算未完成就退出时，下次打开继续处理，无需重新建立媒体库。

如果提示保存失败，原先已生效的配置仍保持，请按提示修正后再保存。

别名遵循以下规则：

- 按字面词元处理，不支持正则表达式或通配符；不要把 `.*`、`*PV*` 当作模式。
- 分类名称不能为空；除“混合特典”外，分类至少需要一个有效别名。
- 同一个别名不能分配给两个不同分类；大小写、全半角或常见分隔符变化也可能被视为重复。
- `Specials`、`Extras`、`Bonus`等通用名称保留通用语义，不能用来代表某一种具体类型。
- “混合特典”由多种具体标记共同命中产生，只提供显示名称编辑。

内置名称默认跟随简体中文、繁体中文、日文和英文切换。你自行填写的显示名称按原文显示，不会自动翻译。本版不提供删除分类功能。

### 新增自定义分类

例如，你的库把角色短节目统一写成 `Character Mini`：

1. 在分类管理中点击“新增分类”。
2. 分类名称填写“角色短节目”。
3. 识别别名填写 `Character Mini`，需要时另起一行填写其他实际使用的写法。
4. 依次保存编辑弹窗和分类管理主弹窗。
5. `作品.Character.Mini.01.mkv` 或该类型目录中的资源便可按新规则识别；也可以在资源菜单中人工指定。

别名建议选择明确且不容易出现在普通片名中的词组，避免使用 `A`、`Video`、`Disc` 等过于宽泛的词。

如果想把 OAD 从默认的“OVA / OAD”中独立出来，可先编辑原分类，移除 `OAD`、`OADs` 别名，保留 OVA／OAV 别名；再新增 OAD 分类并接收这两个别名，最后保存分类管理主弹窗。仅修改原分类的显示名称不会拆分类型，已有人工分类也不会自动转入新类型。

## 六、手工纠正单个资源

打开资源卡片的更多菜单或右键菜单，选择 **修改特典类型**。

| 选择 | 结果 |
| --- | --- |
| 自动识别 | 清除人工分类，重新按当前规则判断 |
| 非特典 | 明确指定该资源不是特典，之后自动扫描和规则重算会尊重这个选择 |
| 某个内置或自定义分类 | 将资源固定为所选类型 |

这项操作只修改分类，不修改作品关联、季号、集号或版本。作品归属错误应使用作品关联功能；季集错误应使用原有的手工季集映射功能。

对于电影中的待确认正片，确认文件确实是正片后，可标记为“非特典”，使其成为正片候选。不要把所有待确认资源批量当作正片。

资源的来源信息可用于查看原始文件名、分类来源及命中词。规则修改后某个资源始终没有变化时，先检查它是否已有人工分类；需要重新判断时选择“自动识别”。

## 七、命名规范建议

无需为了使用本功能批量改名。先扫描并核对结果，对已有库可优先补充别名或手工纠正。以下结构适合整理新资源。

### 1. 每部作品单独一个目录

建议采用“作品目录 → 正片／季目录与特典目录”的结构，避免将多部作品的 `PV01.mkv` 混放在同一个公共特典目录。

电视剧示例：

```text
剧集库/
└─ 示例剧集 (2024)/
   ├─ Season 01/
   │  ├─ Example.Show.2024.S01E01.mkv
   │  └─ Example.Show.2024.S01E02.mkv
   └─ Specials/
      ├─ NCOP/
      │  ├─ Example.Show.2024.NCOP.01.mkv
      │  └─ Example.Show.2024.NCOP.02.mkv
      ├─ NCED/
      │  └─ Example.Show.2024.NCED.01.mkv
      ├─ PV/
      │  └─ Example.Show.2024.PV.01.mkv
      └─ NEXT/
         └─ Example.Show.2024.NEXT.01.mkv
```

电影示例：

```text
电影库/
└─ 示例电影 (2024)/
   ├─ Example.Movie.2024.2160p.mkv
   └─ Extras/
      ├─ Trailer/
      │  └─ Example.Movie.2024.Trailer.01.mkv
      ├─ Interview/
      │  └─ Example.Movie.2024.Interview.01.mkv
      └─ MENU/
         └─ Example.Movie.2024.MENU.01.mkv
```

电影特典不需要、也不建议人为创建 S00 季集编号。

### 2. 类型标记、序号与说明分开

推荐结构：`作品名.年份.类型.序号.说明.扩展名`。

```text
Example.Show.2024.NCOP.01.mkv
Example.Show.2024.NCOP.02.Final.Version.mkv
Example.Show.2024.EYECATCH.01.mkv
Example.Movie.2024.Interview.01.Director.mkv
```

点号、空格、下划线、连字符均可使用，建议在同一作品内保持一致。序号使用 `01`、`02` 等便于人工核对；分类序号与电视剧正式集号是两回事。

### 3. 一个具体内容尽量只写一个类型

- NCOP 直接写 `NCOP`，不必再加一个通用 `SP` 前缀；`SP.NCOP` 会表达两种具体类型，可能进入“混合特典”。
- 普通 PV 不建议写成 `PV.Trailer`；如果确实是 PV 与预告的合辑，才保留两个标记。
- 共享 `NCOP&ED` 目录可以继续使用，但文件名最好明确写 `NCOP` 或 `NCED`。仅写 `01.mkv` 无法从该目录确定唯一类型。
- `Specials` 适合做通用容器；希望文件直接归入 SP 时，应使用 `SP`／`SPs` 或文件名中的明确标记。

### 4. 保留正确的正式季集编号

有 TMDB 正式特别篇对应关系的资源，应保留准确的 `S00E编号`；你已经确认的手工季集映射也应继续保留。

没有正式编号的 NCOP、PV 等，可只使用类型与独立序号，让现有入库流程为电视剧追加特别篇编号。不要为了分类效果自行套用别的正式特别篇集号，以免关联到不相干的标题和简介。

已有 `S0E052`、小数集说明等命名无需因本功能统一改写。分类识别不代表该编号已通过 TMDB 对应关系校验；季集关系有误时，应单独核对映射。

### 5. 留意排除目录与光盘边界

- 名为 `SCAN`、`SCANS`、`CD`、`CDS` 的目录不参与扫描识别；大小写及外层装饰兼容，如 `scans`、`《CDs》`。不要把希望入库的视频放在这些目录中。
- `MENU` 分类指普通视频文件形式的菜单影像，不是 Blu-ray／DVD 的交互菜单。
- ISO、真实 BDMV 结构和盘内菜单继续使用原有光盘播放入口，不按普通特典视频处理。发行目录名中出现 `[BDMV]`，本身不代表它就是实际光盘结构。

## 八、常见问题

**改完显示名，旧文件怎么没有按这个名称识别？**

显示名与别名是两个设置项。请把要识别的实际写法加入别名，并在分类管理主弹窗保存；已有自动分类会逐批更新。

**为什么是“其他特典”？**

通常已有 Specials／Extras 等通用证据或 S00 身份，但没有识别到具体类型。可以补充明确子目录、文件标记、别名，或手工指定。

**为什么是“混合特典”？**

文件名同时命中多种具体类型，或没有具体文件标记而继承了混合目录。先查看来源信息，再决定是保留合辑含义，还是修正名称／人工类型。

**修改类型后，为什么集号或作品归属没有改变？**

分类与作品、季集分别管理。修改类型不会重新编排 S00，也不会把资源自动移到另一个作品。

**电影没有默认播放按钮可用怎么办？**

先在“待确认资源”或“特典映像”中显式选择文件。确认某一资源确为正片后，可将其标记为“非特典”；不要将菜单或预告当作正片候选。

**能否直接扫描本地 STRM 库入库？**

本功能保留当前本地文件夹不支持 STRM 入库的边界。名称规则可用于已有支持来源中的资源，但分类功能不会扩大来源支持，也不会为了识别类型读取 STRM 内容或访问其目标。
